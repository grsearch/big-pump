# Pump Signal

Pump.fun 毕业币的 X 讨论监控、24 小时生命周期和长持型聪明钱包研究系统。不会创建、签名或发送交易。

## 本地运行

要求 Node.js 24+。本项目已经安装依赖。Windows 可在 PowerShell 中运行 `./Start-Signal.ps1`，然后访问 http://localhost:3000。程序启动 dashboard 和绑定到 127.0.0.1:5010 的 SQLite 后台。终止启动窗口即可停止程序。不可直接暴露后台端口到互联网。

其他环境：安装锁文件依赖后执行 `node scripts/start.mjs`。单独运行后台可执行 `node --env-file-if-exists=.env backend/server.mjs`。测试使用 `node --test --test-isolation=none tests/*.test.mjs`；界面检查使用 `pnpm exec tsc --noEmit` 和 `pnpm run build`。

## 密钥与开关

将 `.env.example` 复制成 `.env`，只在本地文件中填写：

- `HELIUS_API_KEY`：Business API 密钥。
- `X_BEARER_TOKEN`：X 开发者应用 Bearer Token。
- `ENABLE_X=true`：允许付费 X 搜索。默认 false。
- `ENABLE_WALLET_RESEARCH=true`：允许自动钱包发现与历史扫描，消耗 Helius 额度。默认 false。
- `AUTO_START=true`：后台启动后自动采集。默认 false，可在 dashboard 点击启动。

修改环境变量后重启后台。密钥不进入前端、Git 或私有演示站点。没有密钥时不会伪造真实数据。`data/pump.db` 为本机数据文件；备份时先停止后台或使用 SQLite 在线备份，以包含 WAL 数据。

## 已实现

- 深色中文 dashboard：Symbol、CA、FDV、主迁移池 LP、Holders、项目 X、聪明钱包累计买入/当前持有、作者增长、状态、费用、详情图表和帖子证据。
- Helius confirmed 日志监听，按官方 Pump IDL 校验迁移事件及调用上下文，CA 去重。断线有限补漏（100 笔）；达到上限明确记缺口。不是无遗漏的生产级全链索引。
- DexScreener 每 30 秒批量补主迁移池行情；休眠币约 2 分钟检查。Holders 用 Helius 分页按非零余额 owner 去重，超出分页上限返回未知。包含池等协议所有者，未作为净散户人数。
- X recent-search 只查询列入监控后的新增区间，优先 CA，账号关联经人工核对后允许名称扩展。无 7 天回查。30 秒/120 秒目标轮询，单个串行调度，币多时实际延迟增加。
- 请求前按最大返回数预留费用，返回后按资源去重结算。失败保留预算预留并退避。费用为保守估算，不是官方账单。建议同时在 X 控制台设置消费上限。
- 默认每日 $10、每币 $0.50；规则页可修改。X 搜索一次至少 10 条的请求容量，剩余预算不足最小请求时休眠。
- 最大 AGE ≤24 小时；低 FDV 持续判断、无增长休眠、晚期筛选、冷却与最多两次唤醒。手动休眠不会自动唤醒。唤醒不重置费用或 AGE。
- 聪明钱包按 FIFO 数量/成本批次计算：实质长持比例、已卖出对应成本回收倍数、闭合样本数与整体已实现 SOL 收益。归属时间独立保存，不回填历史信号。
- 持久化后台，真实与演示明确分离。演示操作只保存在页面内存。

## 钱包发现与覆盖

自动研究从 FDV ≥$100K 的被监控池获取最近 20 笔交易样本，识别可解析的 SOL 单币兑换，再为候选钱包排队扫描历史。支持手动输入钱包启动扫描。历史扫描每页 100 笔，每分钟至多一页，每轮上限 50 页；达到上限需要手动继续，进度持久化。

只有完整扫描且没有未知代币转账/不支持兑换的钱包，才可能满足验证门槛。未知毕业时间的币参与成本统计但不获得“早期”资格。默认至少 10 个完整仓位样本、3 个合格长持盈利样本。未达到数据覆盖条件的结果保持候选/观察，不捏造 smart wallet 数字。

目前仅支持 Helius Enhanced 可明确归属的 native SOL 单币交换，手续费按同币 SOL 口径计入；不支持复杂路由、多币兑换、账户间成本搬运、美元历史收益或所有类型的 MEV/内幕识别。当前解析对未知情况保守拒绝验证。池子样本发现不是完整逐笔索引，可能漏掉早期买家。研究队列需要持续运行才能积累样本；候选不等于经过充分检验的投资信号。

## 已知限制与后续上线检查

1. 没有配置用户密钥，未进行 Helius/X 私有接口端到端实测；实际授权、响应结构、覆盖与延迟需接入后检查。
2. 当前采用有预算预留的增量搜索，未接入 X Filtered Stream。名称查询必须结合经核对的账号，优先减少老币混淆，可能漏掉仅提名字的帖子。
3. 价格增长信号暂为相邻有效快照 FDV 增长 ≥5%；不是新买家增长的替代证明。没有把无法获取的新买家数展示为真实指标。
4. 帖子查询每币最近 5000 条参与窗口分析，超大量讨论时首次作者统计受此上限影响。需大规模运行时改为聚合表及定期数据保留策略。
5. 本地 HTTP API 只允许 loopback Host 和本地 dashboard Origin；远程私有站点只是演示界面，不运行持续采集器。长期运行需要常驻电脑或服务器，不依赖打开浏览器。
6. 启动/停止控制不保证撤销已经发出的外部请求；有未决请求时的最坏费用已预留。X UTC 计费日切换及供应商定价变化应以账单为准。
7. WebMCP 仅提供视图导航，环境没有可用验证上下文，未声称完成交互验证。

## 新增：过滤、AI 评价与 Shadow（2026-09-10）

### 内容过滤

`lib/social.ts` 为确定性内容筛选，不认证账号身份。截图形式的 CTO radar、ATH MC / LIQ / Holders / Top10 / Snipers 等多字段行情模板记作 broadcast，权重 0；跨数字/币名替换的模板重复权重 0；明显推广权重 0.25，暂不进入核心作者数及 AI 样本；其他正文权重 1。负面讨论不会仅因负面被删除。原帖仍保存，可在详情查看原因。

这是读取之后的过滤，不能退回已产生的 X 费用。未查询账号粉丝网络，也不能保证过滤所有协同营销。过滤规则会有误判，应通过人工抽样复核。

### DeepSeek / 智谱

在本机 `.env` 中填 `DEEPSEEK_API_KEY` 或 `ZHIPU_API_KEY`；设置 `AI_PROVIDER=deepseek`、`AI_MODEL=deepseek-flash`（智谱可用 `AI_PROVIDER=zhipu`、`AI_MODEL=glm-4.5-air`），最后 `ENABLE_AI=true`。默认关闭。API 密钥不进前端。仅将已采集的公开帖子正文、作者 ID 和代币标识发送给所选提供商。

每币最少间隔 5 分钟，有效样本须至少 10 帖 / 5 位作者，每作者最多 2 帖，每次最多 40 帖、每帖 600 字符。相同内容哈希不重复调用，默认每日最多 100 次请求（包括失败），是次数上限而非美元金额硬上限。输入有长度上限、输出 1800 tokens，未开启网页搜索或工具执行。

五个维度：讨论态度、叙事清晰度、论据具体程度、观点参与度、操纵话术风险。总指数 = clamp(态度×20% + 叙事×20% + 论据×30% + 参与×30% − 风险×30%, 0, 100)。指数不是上涨概率。任一维度未知则总分未知；每项评分必须有真实输入帖子 ID。摘要、完整证据、模型/提示词版本、生成完成时间和 token 用量均保存。失败、截断、非法 JSON 或无效证据不会生成可用于交易筛选的分数。AI 只评输入样本，并非全 X 舆论或事实核查。

### Shadow v1

在 dashboard 的 Shadow 测试页创建实验，两组各 $1,000 模拟资金，默认每笔 $50，不设持仓数量上限，仍受各组可用模拟资金约束（现有实验也不再限制 5 个仓位）。参数在实验开始时冻结。A 使用基础有效讨论与市场门槛，B 额外要求有效 AI 指数 ≥65、风险 ≤40、证据充分度 ≥60%；AI 结果必须在决策前已完成且不超过 10 分钟。

共同门槛：15 分钟内 ≥10 条有效帖子及 ≥5 位作者；FDV $20K–$2.5M；LP ≥$15K；AGE ≤12 小时；行情不超过 60 秒。每币每组最多一次尝试，不反复追入。

成交：信号后等待至少 15 秒且时间更晚的新行情，重新检查入场条件。使用 USD 单价、LP/2 作为合成恒定乘积池储备估计，另扣默认双边各 1% 滑点、1.25% 手续费及每次 $0.05 固定成本。这不是 Jupiter 可执行报价，费用为实验假设，无法复现 MEV、失败交易、真实池路由与精确滑点。绝不可把结果当作实际成交回报。

退出：参考市场价格下跌 25% 发出止损信号；达到入场参考价 2 倍卖 50%，余仓从观察到的最高价回撤 30% 退出；最长持仓 6 小时；币休眠/归档或毕业达到 24 小时发出退出。所有卖出仍等待新快照，跌穿时以之后观察价格估算，不保证止损价。缺行情时不伪造卖出，权益显示无法估值，最大回撤统计只覆盖可估值时点。

即使 X 已停止，未平的 Shadow 仓位仍请求行情。暂停开仓后已有持仓继续管理；必须清仓才能结束实验。关闭整个采集器会停止模拟推进；重启按新行情继续，不补造离线期间的成交。利润不扣 X 与 AI 研究成本，两组费用应另行分摊。

当前新增规则与 mock 接口测试已覆盖图中模板、负面观点保留、证据 ID 验证、未来数据隔离、延迟成交、跌穿止损与缺行情。真实 AI 供应商尚未用用户密钥调用，识别准确率和策略盈利能力尚未验证。

聪明钱包额外要求链上 AGE 严格大于 30 天，可在规则页修改。以历史扫描中最早的成功链上交易计算年龄下限；未知年龄、恰好 30 天或不足 30 天均不会成为候选或已验证钱包。修改规则和重启服务时会重新评估已有标签。CA 在代币列表和详情中可点击前往 GMGN，旁边保留复制按钮。

### X 请求错误与恢复
首次搜索在加入监控（或唤醒）至少 45 秒后进行，时间参数采用整秒 UTC；这是保守的索引和时钟余量，不回查加入之前的帖子。
HTTP 400/401/402/403/422 会暂停所有 X 搜索并持久保存暂停状态，重启也不会反复请求。检查参数、运行中服务的环境变量、App 权限及账户额度后，在 dashboard 点击“重试 X（配置已检查）”。更新 .env 后须重启后台才能加载新密钥。401 仅说明认证未通过，不足以断言 Token 被撤销。429 按重试时间退避。明确拒绝会释放本次内部预算预留；网络异常或服务端错误仍保留预留待核账。历史遗留预留不自动删除，实际费用以 X 账单为准。
Linux 前台生产服务分别运行 pnpm collector 和 pnpm start:dashboard，后者显式绑定 127.0.0.1:3000，避免读取 PORT=5010 后与采集器冲突。两者需使用 Node 24+。systemd 的 WorkingDirectory 应指向项目目录，ExecStart 使用独立 Node 24 的绝对路径；不要替换其他应用使用的系统 Node。SSH 隧道需同时转发本地 3000 和 5010 到服务器同端口。

### 行情缺失与迁移池
CA 批查可能只返回毕业前的 Pump.fun 池。系统缺少有效迁移池 FDV/LP 时会按链上事件保存的 pool 地址批量直查；始终同时核对 Solana 链、CA 和池地址，不用旧池或同名币代替。Dashboard 显示逐币行情错误。行情缺失、失败、过期或 FDV 低于退出门槛时不调用该币 X 搜索；连续 5 分钟没有有效行情进入数据休眠，保留低频行情查询。行情恢复且 FDV 达标时可恢复观察；已低于门槛则继续休眠。正常观察币仍按默认连续 3 分钟低 FDV 进入休眠。

### Stonk 并行监控（首版）
在已有 .env 中加入 ENABLE_STONK=true 后重启采集器。需要已配置的 Helius；不需要 Stonk API key。该开关只开启发现与核验，不改变 ENABLE_X、ENABLE_AI 或总预算。
- Pump 监听保留，另订阅 Stonk 两个 LaunchLab 平台配置的日志。迁移必须是成功交易中的 migrate_to_cpswap，核对 LaunchLab 程序、平台配置和 CPMM 程序，读取实际 mint、新池和 blockTime。AGE 以链上时间为准。
- 官方毕业列表每 60 秒读取第一页和一页历史分页作为发现/补漏；只有 launchpad=launchlab 且 status=graduated、报告时间在 24 小时内的币进入待核验队列。旧 CLMM 直接建池不计入毕业币。
- WebSocket 迁移签名直接核验；漏失候选按池地址分页回查签名，每次 100 条、单候选每分钟最多推进一页，每页最多查 3 笔靠近报告毕业时间的交易。高交易量代币可能需要更长核验时间，未核验币不消耗 X 预算。接口限流和格式变化会延迟发现，待核验数量展示在页面。
- DexScreener 继续按迁移池直查；缺失时每轮最多补查 2 个 Stonk 官方 USD 行情，逐币间隔至少 60 秒，必须与链上核验的新池和 CA 一致，且源时间不超过 60 秒。
- Dashboard 新增来源筛选、计价资产、转账税率和 Stonk 连接状态。两来源共用 X 总预算和退出规则。
- Stonk 已接入 Shadow 和聪明钱包统计：仅在税费、计价行情可核验时进入模拟；历史汇率缺失的交易保留但不用于盈利资格验证。
验证依据：Stonk 官方开发者页面 https://www.stonkfun.xyz/developers ，Raydium 官方 IDL https://github.com/raydium-io/raydium-idl/blob/master/raydium_launchpad/raydium_launchpad.json 。平台配置地址参照 Stonk 数据接口文档 https://docs.bitquery.io/docs/blockchain/Solana/stonkfun-api/ ，接入后仍以链上指令验证。

### Stonk 税费与钱包收益
Shadow 使用 USD 现金、USD 价格和池流动性估算成交，每次买入扣计价币入池税及基础币出池税，卖出反向扣税；税费按链上当前 epoch 规则向上取整并应用单次 maximumFee。每笔成交保存税费配置快照。计价币涨跌已体现在 USD 市场价格中。仍是恒定乘积近似，保留原有滑点、交易费和网络费估值，不是链上可执行报价；额外路由换币成本没有精确报价。遇到税费过期、未知扩展或计价资产无报价时停止新入场，持仓标记无法估值。
聪明钱包从 Helius 的钱包实际 tokenBalanceChanges 识别简单双资产 Stonk SWAP（当前限 feePayer 作为交易者），实际收付数量已经包含转账税，不会再次扣税。交易费用按当时已采集的 SOL/USD 汇率计入；计价币按同一时刻之前最多 120 秒的已采集汇率换算 USD。绝不拿今天价格回填过去。复杂多资产交易、代付交易或缺少余额数据的交易不做确定盈利判断。
USD 与 SOL 分别展示和计算，资格要求历史覆盖及成本/汇率完整、两类收益均非负且至少一类为正，避免把亏损币种藏在另一币种的盈利中。USD 交易最低投入默认 $10，可在规则页修改；其余早买、长持、高倍数、完整样本、AGE >30 天要求保留。旧钱包重新点击“分析钱包”会按新版解析器全量回扫；历史价格不足时只能积累后续有价格记录的样本，不伪造历史收益。Stonk 可计入已验证钱包买入/持有数量；标签仅对验证之后的交易生效。钱包地址可打开 GMGN，复制另设按钮。
