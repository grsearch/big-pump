# C 策略实盘（Jupiter）

代码默认关闭，不需要改动原有 Shadow 实验。新的「实盘 C」页面展示独立订单、链上确认持仓、SOL 收益和跳过原因。当前版本通过模拟响应测试；没有使用真实资金验证成交。

## 服务器所有者配置

申请 Jupiter Free API Key，在服务器 `.env` 填写 `JUPITER_API_KEY`。免费套餐按每组织 60 次/分钟的滑动窗口配置；同组织其他程序会共享额度。如果升级套餐，手动调整 `JUPITER_REQUESTS_PER_MINUTE`，不要只改数字而未升级。

准备专用 Solana 钱包。将 Solana CLI 格式的 64 字节密钥数组 JSON 放在仓库之外，仅服务账户可读；在 `.env` 中填写 `LIVE_WALLET_KEYPAIR_FILE` 的绝对路径和匹配的 `LIVE_WALLET_ADDRESS`。不要在聊天、网页或 Git 中提交私钥。现有 `HELIUS_API_KEY` 用于模拟及链上确认。

以下默认值可以在服务器配置；部署更新本身不会启用交易：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| ENABLE_LIVE_TRADING | false | 所有者改为 true 后，后端才加载签名钱包 |
| JUPITER_REQUESTS_PER_MINUTE | 60 | 此程序可使用的共享报价额度 |
| LIVE_SLIPPAGE_BPS | 1500 | 买卖滑点上限 15%，失败不会自动提高 |
| LIVE_PRIORITY_FEE_LAMPORTS | 300000 | 买卖固定优先费 0.0003 SOL；基础费和租金另计 |
| LIVE_MAX_FEE_LAMPORTS | 5000000 | 单笔网络/优先费/租金总上限 0.005 SOL，不含买入本金 |

安装新依赖、运行测试和构建、重启后，在「实盘 C」检查地址、费用限制与配置状态。由所有者勾选每笔 0.1 SOL 并点击「启用实盘 C」，才开始接收新信号。私钥只保留在后端进程内，不经过前端。继续使用原有 nginx Basic Auth 保护整个页面和 API。

## 交易行为

- 买入输入固定 100,000,000 lamports，即 0.1 SOL；每币实际买入一次，不补仓。没有 5 个持仓上限。
- 入监控的新 Stonk 毕业事件触发买入，必须发生在本次启用之后且不超过 2 分钟。无需 X 作者、FDV 或 LP 研究门槛，不等待 15 秒。是否能成交以 Jupiter 即时报价及实际链上执行为准，Shadow 的估算模型报错不会替代实盘路由核验。
- 获取 Jupiter 买入订单和反向卖出路由，核验数量、滑点、费用、付款者，并查询钱包余额；不再调用额外的 simulateTransaction 预执行。签名前再次核验条件。首版只接受本钱包作为付款者的单签交易，排除 JupiterZ 的多签 RFQ 路由。Stonk 是否可交易以实际链上执行结果为准。
- 新买入不用 Shadow 的 15 秒模拟延迟；实际仍需报价、核验、签名、提交与确认。Stonk 的中间计价币由聚合路由处理，到账税费以实际钱包变动为准，不将 Shadow 税费再扣一次。
- 先持久化签名和订单，再提交。只根据 finalized 链上回执登记买入与卖出，HTTP 成功不等于成交。不确定结果不重发、不另买；程序重启继续核对同一签名。
- 毕业核验入库后立即唤醒实盘，不等待下一轮定时检查。临时网络失败、服务错误、无路由或限流在毕业后 2 分钟内最多尝试 6 次，间隔 1、2、4、8、8 秒，限流遵守更长的等待时间。费用、滑点和余额核验失败不自动放宽。已提交或结果不确定的订单不重发。
- 迁移签名由独立的一秒调度器处理，WebSocket 新事件直接唤醒；每批最多并发 4 条，优先处理最新 3 条迁移并保留 1 条创建/旧记录核验机会。列表补漏独立推进。未完成签名持久化退避重试，最长间隔 60 秒，在 24 小时发现范围内不再因达到 5 次而永久停住。旧版未分类签名作为后台记录继续处理。排队过久的旧毕业币不会绕过买入时间窗口补买。
- 实盘买卖均取消本程序额外的链上模拟；Jupiter 服务内部的交易构建或检查不由本程序控制。失败仍可能产生链上手续费。已有模拟错误详情保留展示。
- 持仓目标每 5 秒检查卖出报价；已触发退出和到期仓位优先，普通持仓检查与新买入轮流处理，避免新毕业信号一直排在所有持仓之后。每分钟为退出保留最后 12 次请求。多仓、慢请求和共享额度限流会延长间隔，页面保留报价时间与错误。
- 净卖出报价达到成本的 140%（盈利 +40%）激活移动止盈，之后从最高净回收金额回撤 10% 全卖；无固定止盈止损，最长持仓 30 分钟。触发后保留退出意图，失败继续尝试新报价，不撤回触发条件。无路由时无法保证退出。
- 成本和收益按钱包实际 SOL 变化计入网络费、租金与交易费用；平台/转账税通过实际净到账体现。未成交不算收益。失败买入费用在总体净已实现中扣除，失败卖出费用加入该仓位成本。
- 「暂停新买入」继续管理已有仓位。停止采集也会停止新买入，但独立实盘定时器继续卖出。停止后端进程则无法执行退出。重启时保留原有开仓开关；不要配置进程在多个实例中共用同一钱包或数据库。

## 待核对订单

优先费通过 Jupiter `/order` 的 `priorityFeeLamports` 和 `broadcastFeeType=exactFee` 设置，`jitoTipLamports=0` 不额外添加 Jito 小费；买卖报价与反向路由检查使用一致设置。基础费由网络规定。费用仍受 `LIVE_MAX_FEE_LAMPORTS` 总上限约束。服务器可显式加入 `LIVE_PRIORITY_FEE_LAMPORTS=300000` 并重启，以实盘页面显示的运行配置为准。

升级到 15% 滑点时，服务器若已有 `LIVE_SLIPPAGE_BPS=100`，必须改为 `LIVE_SLIPPAGE_BPS=1500` 并重启后台；旧环境变量不会随 Git 更新。以实盘页面显示的运行值为准。15% 是相对报价的最大容许滑点，不是固定手续费。

订单一直显示「等待链上核对」时先在 Solscan 和钱包检查同一签名，并确认 Helius 服务正常。首版不自动判定“未查到”就是失败，也不提供网页强制清除功能。未确认买入会阻止新的开仓，但不阻止其他仓位退出。长时间无法确认需要人工核账；不要删除数据库或改签名让程序重买。持仓数据独立保存，观察列表清理不会删除实盘账本。

专用钱包不要同时手动交易或由其他程序操作，否则余额与持仓账本可能不一致。程序不自动接管外部持仓、充值代币或人工卖出，余额不一致会拒绝提交并显示错误。

官方接口依据：[Order](https://developers.jup.ag/docs/api-reference/swap/order)、[Execute](https://developers.jup.ag/docs/api-reference/swap/execute)、[限流规则](https://developers.jup.ag/docs/portal/rate-limits)。API 订阅费和每笔交易费用是两类成本。

从 A 升级到 C 时关闭新开仓，需要在实盘 C 页面重新启用。旧 A 订单与账本保留，已有 A 持仓继续原 +100% / 回撤20% / 30分钟规则；C 新仓使用 +40% / 回撤10% / 30分钟。Shadow C 的最长持仓同步改为30分钟；未成交的旧15分钟退出意图会重新核验，历史成交不修改。
